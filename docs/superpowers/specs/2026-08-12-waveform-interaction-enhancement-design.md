# DiCar Tune App 波形工作台交互增强设计规格

- 状态：已确认
- 日期：2026-08-12
- 主产品：Windows 桌面 App
- 参考项目：`zbk666/IKUN-CAR-LAB`（只读产品体验参考）

## 1. 目标

在现有 Windows App 八通道波形工作台上增加调车所需的高频交互能力：工作组、实时数据探针、A/B 双游标、差值读数和 Y 轴范围模式。

本阶段只扩展现有 React/Canvas 波形组件，不改变 DCTP、Rust `AppActor`、设备 Manifest 协议或桌面 Bridge 合同。现有下列约束继续作为不可回退的质量门槛：

- 同时最多显示 8 个通道，并继续服从实际串口硬件的链路预算。
- 每通道最多保存 30,000 点，八通道总缓冲保持有界。
- Canvas 使用像素级极值降采样，不能为每个样本创建 DOM 节点。
- UI 可视更新不超过 30 Hz。
- Canvas 不是唯一信息载体；表格、文本状态和键盘操作必须保持可用。

## 2. 方案选择

评估三种方案：

1. **扩展现有 `WaveformPanel`、`WaveformCanvas` 和遥测缓冲（采用）**：保留现有数据路径，只增加独立的交互纯函数和视图状态。
2. 引入第三方图表库：可快速获得游标组件，但会重复现有 Canvas、增加高频性能风险，并破坏当前降采样与无障碍回退路径。
3. 新建独立“高级示波器”页面：隔离度高，但会产生两套订阅、缓存、快捷键和状态真值。

采用方案 1。参考项目只提供产品体验启发，不复制其 PySide6/pyqtgraph 实现，也不引入它的字符串 JSON 协议字段体系。

## 3. 现有架构中的位置

数据路径保持不变：

```text
DCTP telemetry
  -> Rust AppActor 有界事件
  -> DesktopBridge
  -> workspaceStore
  -> TelemetryRingBuffer
  -> WaveformPanel
  -> WaveformCanvas + TelemetryDataTable + TelemetryLegend
```

本阶段新增两个无副作用的 TypeScript 模块：

- `telemetry/waveformInteraction.ts`：时间与像素换算、最近样本查找、A/B 状态转换、游标键盘步进和范围约束。
- `telemetry/telemetryWorkgroups.ts`：根据 Manifest 遥测描述符生成工作组，并按链路预算生成可选择的通道集合与裁剪说明。

`WaveformCanvas` 仍只负责绘制和把指针位置转换为交互事件，不保存业务状态。`WaveformPanel` 是工作组、探针、A/B 游标和 Y 轴模式的唯一视图状态所有者。

## 4. 波形工作组

### 4.1 数据来源

首版不增加设备协议字段。工作组根据现有 `TelemetryDescriptor` 的 `machineName`、`displayName` 和 `unit` 进行确定性分类。

内置工作组按以下优先顺序生成：

1. 速度：`speed`、`rpm`、`velocity`、`target_rpm`、`actual_rpm`、速度相关中文名称。
2. 航向与姿态：`yaw`、`heading`、`gyro`、`angular`、航向、角速度、陀螺仪。
3. 编码器：`encoder`、`pulse`、`count`、编码器、脉冲、计数。
4. 电机：`motor`、`pwm`、`current`、`torque`、电机、电流、扭矩。
5. 电源：`battery`、`voltage`、`power`、`adc`、电池、电压、电源。
6. 全部通道：包含当前 Manifest 的所有遥测描述符。

匹配不区分大小写。一个通道可以出现在多个语义工作组；工作组内部始终保持 Manifest 原始顺序。只有至少包含一个通道的工作组才显示。

未来车型配置层可以用稳定描述符 ID 或 machine name 覆盖分组和显示顺序，但不能改变设备声明的类型、单位、权限或链路预算。

### 4.2 选择与订阅

- 选择工作组只更新“待应用通道”，不自动向车辆发送订阅。
- 用户必须点击现有“应用 N Hz 订阅”才改变真机负载。
- 工作组少于链路允许通道数时全部保留。
- 工作组超过链路预算时，按工作组顺序保留前 N 个，并显示“已保留 N 个，省略 M 个”；不能静默裁剪。
- 工作组为空或 Manifest 更新后原工作组消失时，回退到“全部通道”的前 N 个可用通道。
- 手工勾选通道后，工作组显示为“自定义”，现有至少 1 路、最多链路允许路数的校验继续生效。

## 5. 探针与 A/B 双游标

### 5.1 时间戳是真值

所有交互状态使用设备遥测时间戳，禁止用某一通道的数组索引代表其他通道的同一时刻：

```ts
type WaveformCursorState = {
  probeTimestampUs: number | null;
  cursorAUs: number | null;
  cursorBUs: number | null;
  activeCursor: "A" | "B";
};
```

每个通道独立查找离目标时间最近的样本。只有当最近样本与目标时间的距离不超过该通道最近可观测采样间隔的 2 倍时，才显示为邻近样本；否则显示“无邻近样本”。样本不足以估计间隔时，只要目标时间位于该通道首末样本范围内即可使用最近样本。

### 5.2 实时探针

- 指针进入 Canvas 后，根据 X 坐标和当前可见时间窗计算 `probeTimestampUs`。
- 指针移动只更新临时探针，不改变 A/B。
- 指针离开时清除探针，并恢复显示活动游标；没有锁定游标时显示最新样本。
- 探针线使用细点线，并在文本读数区标明“探针”，不能与 A/B 混淆。
- 触摸设备不依赖悬停；点击仍能锁定 A/B。

### 5.3 A/B 状态转换

- 没有 A 时第一次单击：设置 A，`activeCursor = A`。
- 有 A、没有 B 时第二次单击：设置 B，`activeCursor = B`。
- A、B 都存在时第三次单击：用新时间替换 A、清除 B，`activeCursor = A`。
- “清除 A/B”同时清除两个锁定游标，但不改变缓冲或订阅。
- A 使用实线和标签 `A`；B 使用长虚线和标签 `B`。两者同时使用不同颜色与线型，不能只靠颜色区分。
- A、B 都存在时显示绝对 `Delta t`，并为每个有邻近样本的通道显示 A 值、B 值和有符号 `Delta value = B - A`。

### 5.4 键盘和标记

只有波形交互区获得焦点时响应快捷键：

- `Space`：沿用现有暂停/继续。
- `Left` / `Right`：把活动游标移动到基准通道的前一个/后一个样本；没有锁定游标时先在最新样本建立 A。
- `Shift + Left` / `Shift + Right`：移动 10 个基准通道样本。
- `A` / `B`：在相应游标存在时切换活动游标；游标不存在时不凭空创建。
- `Escape`：有探针时先清除探针；否则清除 A/B。
- `M`：优先在活动锁定游标处添加标记，其次使用探针，最后使用基准通道最新时刻。

基准通道是当前所选通道列表的第一项。键盘移动只用它选择目标时间，各通道读数仍分别按时间查找。

## 6. 暂停、滚动与数据边界

- 暂停只停止/冻结现有遥测展示语义，不清除探针或 A/B。
- 恢复后 A/B 保持原时间位置，即使最新窗口已向前移动。
- 若游标时间仍在 60 秒缓冲中但不在当前可见窗口，读数继续保留，并提示“游标位于当前窗口外”。
- 若数据滚动导致游标时间早于所有所选通道的最早有效时间，将该游标约束到最近有效边界，并通过非阻塞状态提示“游标数据已滚出缓冲，已移至最早样本”。
- Manifest 更新时删除已不存在通道的选择与读数。若基准通道被删除，使用新的第一项作为基准，但不擅自改变 A/B 时间。
- 断线后沿用现有冻结波形与 Unknown 状态；保留可读缓冲和 A/B，不伪造新样本。

## 7. Y 轴范围模式

每个通道继续使用独立纵向带区，避免不同单位共享同一比例。

- 局部：根据当前可见时间窗内该通道样本自动计算范围，保留合理边距。
- 全范围：根据该通道当前 60 秒有界缓冲计算范围。
- 固定：切换到该模式时冻结每个已选通道当时的局部范围；后续新样本不改变范围，直到用户选择“重置固定范围”、切换通道或离开固定模式。

常量信号使用以当前值为中心的最小可见范围，避免除零。非有限数值不参与范围计算，并在诊断/文本读数中标为无效样本。

## 8. 组件改动

### `WaveformPanel`

- 管理工作组、探针、A/B、活动游标、Y 轴模式和固定范围。
- 继续调用现有 Bridge 完成订阅、暂停和标记。
- 将所有交互状态转换为 Canvas props 和文本读数模型。

### `TelemetryToolbar`

- 增加工作组选择、Y 轴模式、清除 A/B 和固定范围重置。
- 保留采样率、订阅、暂停、标记、通道选择和时间窗。
- 链路预算裁剪、无数据和交互错误继续使用可访问状态文本。

### `WaveformCanvas`

- 接收探针和 A/B 时间戳、每通道量程以及指针/点击回调。
- 绘制探针线、A/B 线和标签。
- 不保存 React 业务状态，不发起 Bridge 操作。

### `TelemetryLegend` 与 `TelemetryDataTable`

- 图例显示当前优先读数：探针、活动游标或最新值。
- 数据表在 A/B 完整时增加 A、B、差值和样本时间偏差列。
- `role=status`/`aria-live` 文本完整表达目标时间、Delta t、通道值、单位和缺失原因。

## 9. 错误处理

- Canvas 尺寸为零、无样本或无 2D context 时安静保持空态，React 交互不能崩溃。
- 某通道没有邻近样本时只影响该通道读数，不清除其他通道游标。
- 链路预算不足时只修改待应用选择；已生效订阅仍由 AppSnapshot 表示，直到用户确认应用。
- 固定范围对应通道被移除时同时删除该范围，避免陈旧配置污染新 Manifest。
- 所有状态转换均为确定性纯函数，组件不得通过多个相互矛盾的布尔值表达 A/B 阶段。

## 10. 测试与验收

### 10.1 纯逻辑单元测试

- 时间戳与 Canvas X 坐标双向换算及窗口边界约束。
- 不同采样时间、丢包和无邻近样本下的独立最近点查找。
- 第一次、第二次、第三次点击的 A/B 状态转换。
- 普通与 Shift 键盘步进、缓冲滚出后的边界约束。
- 工作组分类顺序、重复归类、未分类通道和“全部通道”。
- 8 路、HC-05 4 路及 9600 baud 2 路预算下的显式裁剪说明。
- 局部、全范围、固定范围和常量信号范围计算。

### 10.2 React/Vitest 交互测试

- 选择工作组不自动调用 `setTelemetrySubscription`，点击应用后才发送。
- 手工选择后进入“自定义”，并保留至少 1 路/最多 N 路限制。
- 指针移动、离开、三次点击、清除和键盘快捷键行为。
- A/B 的 Delta t、各通道差值、单位和“无邻近样本”文本。
- 暂停与恢复不清除锁定游标。
- 标记时间的活动游标、探针、最新值优先级。
- Manifest 更新与链路预算下降后的安全回退。

### 10.3 性能与 App 回归

- 8 通道 x 500 Hz 输入下，每通道仍精确限制为 30,000 点，UI 可视更新仍不超过 30 Hz。
- 新的最近点查询不能在每一帧为所有通道复制完整 30,000 点数组；允许在用户指针事件中进行有界的二分查找。
- 1280 x 720 和 200% 缩放下，工具栏、Canvas、A/B 读数和表格可操作且无水平功能丢失。
- 纯键盘可完成暂停、设置/移动/切换/清除 A/B 和添加标记。
- Canvas、表格与屏幕阅读器状态文本对同一目标时间给出一致结果。
- 现有连接、参数 RAM 写入、Flash 提交、诊断、硬件配置档和安装包构建流程全部回归通过。

## 11. 实施顺序

实现遵循测试先行：

1. 纯工作组分类和预算裁剪。
2. 纯时间/最近点/A-B 状态模型。
3. `WaveformPanel` 与工具栏状态接线。
4. Canvas 探针和 A/B 绘制。
5. 表格、图例和无障碍文本。
6. 性能、响应式、键盘和桌面 App 回归。

每一步先观察相关测试因缺失行为而失败，再写最小实现使其通过。

## 12. 本阶段边界

本阶段不实现：

- 车型 YAML 或外部插件导入。
- 自定义 PID 控制环页面。
- 参数方案、实验档案和曲线对比。
- 赛道或弯道分析。
- 浏览器 DCTP 完整会话。
- 设备协议、Manifest schema 或 Rust Actor 改动。

这些功能继续按已确认顺序进入独立设计与实施阶段。本规格建立的工作组和时间戳交互模型应能被后续车型配置与实验回放复用。
