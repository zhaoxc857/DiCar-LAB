# DiCar Tune 前端 UI 优化设计

## 1. 目标与边界

本轮在不改变现有后端和业务语义的前提下，重构 DiCar Tune 的前端信息架构、视觉层级和桌面工作台布局。设计以“精准控制台”为主体，吸收“赛道指挥席”的高密度遥测与快速扫描能力，并提供共享状态的“标准 / 赛道”双模式。

本轮只修改前端 UI。不得修改 Rust/Tauri、DCTP wire 格式、Bridge 命令、设备状态机、遥测订阅规则、IndexedDB 数据规则、AI 安全边界、录制与回放语义或参数写入行为。新页面必须复用现有 Provider、Store、Hook、控制器和管理器。

本轮不实现无线固件烧录，但要预留真实的前端接入边界，供 UI 优化完成后的无线烧录阶段使用。参数方案导入以及其他既定范围外功能不进入设计。

## 2. 设计原则

1. 默认清楚，按需提高密度。标准模式优先说明、单位和安全上下文；赛道模式提高同屏数据量和波形占比。
2. 状态始终真实。设备、车型、固件、参数、录制和连接信息必须来自现有状态，不再显示硬编码身份或失真的 ComingSoon。
3. 高频任务同屏完成。任务、参数和反馈波形保持可见的因果关系；AI、录制和安全写入保持当前任务上下文。
4. 低频设置退出主视野。连接配置、授权、硬件指南和错误恢复进入右侧连接抽屉，顶部只保留设备健康状态。
5. 视觉变化不得改变运行状态。标准/赛道切换和页面重排不能产生 Bridge 命令、重新订阅、清空草稿或替换实时数据源。
6. 危险操作保持克制。Flash 写入、危险参数和 AI 执行继续使用已有确认、结果反馈和密钥隔离规则。

## 3. 视觉系统

界面采用深色工程控制台基调，不引入大面积霓虹、玻璃模糊或纯装饰动画。视觉令牌分为背景、抬升表面、分隔线、主要文字、次要文字和语义状态：

- 青色：主要交互、选中状态和实时主曲线；
- 绿色：设备正常、连接就绪和成功；
- 琥珀色：偏差、待确认、录制和非致命警告；
- 红色：错误、高风险和失败；
- 中性色：结构、禁用状态和次要数据。

中文是主要界面语言；协议名、单位和工程缩写可以保留英文。普通文本使用无衬线字体，数值、通道、PID、时间与协议字段使用等宽字体。现有一次性按钮、圆角、边框和焦点样式统一到共享组件及语义令牌。

交互反馈控制在约 150–200 ms，并尊重系统减少动效设置。文字与状态达到清晰对比度，键盘焦点始终可见，不能只靠颜色表达错误、连接或危险状态。

## 4. 全局信息架构

顶层产品导航收敛为四个按任务划分的入口：

- 概览：设备摘要、继续调试、最近记录和待处理异常；
- 实时调试：任务、参数、波形、AI、录制状态和安全写入；
- 波形记录：记录库、回放、删除、JSON 导入、JSON/CSV 导出与元数据；
- 诊断：设备健康、连接、协议事件和日志。

连接和设置属于全局能力，不占用顶层页面。参数方案导入没有入口；已有的参数相关操作只在其真实上下文内出现。

/records 必须呈现已有记录管理与回放能力，不再指向占位页面。概览页不再用 ComingSoon 卡片代表已经完成的功能。项目和设备摘要从现有状态派生，不使用 CAR-01 / DEFAULT 等硬编码值。

## 5. 全局外壳与连接抽屉

应用只保留一条全局顶部栏，包含产品标识、四个导航入口、设备状态芯片、帮助和设置。当前常驻的第二条连接控制带被移除。

设备状态芯片始终显示当前设备名称、连接状态和必要的健康提示。点击后从右侧打开连接抽屉。抽屉集中容纳：

- 连接方式；
- 串口或浏览器授权入口；
- 波特率；
- 当前设备与连接健康；
- 硬件指南；
- 连接、断开和现有错误恢复操作；
- 固件摘要和后续无线烧录入口位置。

抽屉只调用现有前端连接能力，不改变 Bridge 状态机。关闭抽屉后，低频字段退出主视野。窄窗口下产品导航折叠为可访问菜单，不能像当前实现一样直接消失。

## 6. 实时工作台与双模式

标准和赛道模式共享同一份设备状态、参数草稿、选中任务、遥测源、录制状态、回放上下文和波形游标。模式切换只改变布局和密度，不允许触发连接、订阅或设备命令。

### 6.1 标准模式

标准模式采用“任务导航 / 参数编辑 / 波形”三栏结构：

- 左栏选择速度环、转向环、电机输出和系统状态等现有任务；
- 中栏显示当前任务的参数、单位、范围、RAM/Flash 状态和说明；
- 右栏显示对应反馈波形、目标曲线、录制状态和现有波形工具。

工作台顶部使用紧凑遥测带显示现有数据中的关键目标值、反馈值、偏差、接收速率、丢样和延迟。缺少某项现有数据时显示明确的不可用状态，不推导或伪造数值。

### 6.2 赛道模式

赛道模式压缩任务和参数区域，扩大波形与关键数字，允许更高的数据密度。单位、连接状态、录制状态和危险提示不得被隐藏。关键操作的点击区域和键盘可达性不因紧凑布局降低。

### 6.3 上下文工具与变更栏

AI 调参、开始/停止录制和记录库快捷入口属于当前任务工具，不占顶层导航。无参数修改时隐藏底部变更栏；真实 dirty 集合非空时才显示放弃、写入 RAM 和保存到 Flash 等现有操作。危险参数与 Flash 写入沿用现有确认流程。

## 7. 页面职责

### 7.1 概览

概览显示真实设备、固件、车型和连接摘要，并提供继续实时调试、最近波形记录和待处理异常的入口。它不复制连接表单，也不显示无法执行的功能卡片。

### 7.2 波形记录

记录库从工作台对话框能力提升为真实页面入口，但继续复用现有 IndexedDB 仓库、录制控制器、导入导出和回放组件。实时工作台仅显示当前录制状态和快捷入口。UI 重构不得改变五分钟上限、自动封存、容量清理、保护记录或异常删除规则。

### 7.3 诊断

诊断信息按设备健康、连接、协议事件和日志分组。默认层展示结论与处理建议，已有原始细节按需展开。不得为视觉完整性制造后端不存在的诊断数据。

## 8. 前端状态与业务边界

界面可以新增不含敏感信息的 workbenchMode 偏好，并使用现有设置存储持久化。除此之外，UI 重构不得改变状态语义：

- 遥测继续来自现有唯一 Bridge 事件入口；
- 不创建第二套订阅、设备缓存或命令通道；
- 实时波形、原始录制和独立回放继续分离；
- 模式切换和页面重排不发送设备命令；
- 参数编辑继续使用现有草稿和 dirty 状态；
- 连接抽屉直接映射现有 Bridge 状态；
- API Key 仍只存在 Windows Credential Manager 和提交请求时的 Rust 内存中。

如果视觉设计需要改变后端、录制、回放、AI、参数写入或连接行为，本轮放弃该视觉设计，不扩大实现范围。

## 9. 无线固件烧录预留接口

连接抽屉增加“固件”区域，显示现有状态能够提供的固件版本，并为后续无线烧录预留入口。UI 优化阶段建立独立的 FirmwareFlashEntry 前端组件边界和 onOpenFirmwareFlash 回调，但不调用设备命令、不注册新的 Tauri 命令，也不实现烧录协议。

预留的烧录向导容器支持以下展示状态：

- 不可用；
- 设备检查；
- 固件选择；
- 烧录准备；
- 烧录进度；
- 成功；
- 失败。

UI 优化阶段能力未接入时，入口必须明确显示“尚未启用”，不能伪装成可执行操作。无线烧录阶段接入能力检测和后端命令后，不应再重排全局导航或连接抽屉。

## 10. 组件边界

优先按界面职责拆分现有大型组件，候选边界包括：

- ConnectionStatusChip 与 ConnectionDrawer；
- WorkbenchModeSwitch；
- TelemetryStrip；
- StandardWorkbenchLayout 与 TrackWorkbenchLayout；
- WorkbenchContextActions；
- RecordingsPage；
- FirmwareFlashEntry。

这些组件只组合现有业务能力，不复制 Store、Hook 或控制器逻辑。共享按钮、卡片、徽章、输入、选择框、抽屉、对话框和状态反馈统一使用前端 UI primitives。

## 11. 响应式与可访问性

设计以 Windows 桌面端为主，重点覆盖 1280×720、1366×768、1920×1080 和高 DPI。宽度不足时，三栏依次变为双栏和纵向布局；连接状态、录制状态、单位和危险操作不能消失。

导航、抽屉、对话框、模式切换、参数控件和回放操作支持键盘操作、可见焦点和正确的辅助标签。加载、空数据、断线、权限不足和设备不兼容使用各自明确的状态，而不是共用一个模糊错误页。

## 12. 清理与验证

实现阶段只删除经引用搜索确认无使用方的占位页面、过期路由、重复样式和废弃 UI 文件。仍被测试、文档或现有功能使用的文件不得删除。设计会话临时目录不进入提交或发布文件。

前端门禁包括：

- ESLint；
- TypeScript 类型检查；
- Vitest；
- 生产构建；
- Playwright 覆盖导航、连接抽屉、标准/赛道切换、实时调试、记录库和回放；
- 验证模式切换与页面重排不会产生额外设备命令。

本轮不修改后端，因此不新增 Rust、DCTP 或 C 行为测试。最终差异审查必须确认 Rust/Tauri、协议和设备逻辑未被改变。

## 13. 验收标准

1. 四个顶层入口均指向真实页面或现有功能，不再把已完成功能标为即将推出。
2. 顶部设备状态芯片与右侧连接抽屉替代常驻连接控制带。
3. 标准和赛道模式共享状态，切换时无额外设备命令和业务状态丢失。
4. 实时工作台在目标桌面尺寸下保持任务、参数与波形的清晰关系。
5. 记录库成为独立真实页面，同时保持原有录制、存储和回放语义。
6. 诊断、空状态、错误和危险操作具有清晰层级与键盘可达性。
7. 无线烧录具有稳定的前端接入边界，但 UI 阶段不包含任何烧录后端逻辑。
8. 前端全部门禁通过，最终差异不包含 Rust/Tauri、DCTP 或设备行为修改。
