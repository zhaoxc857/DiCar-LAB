# DiCar Tune 用户手册

本文面向使用 DiCar Tune 0.1.2 进行智能车或电子设计竞赛车辆调参的参赛者。建议先用内置模拟器熟悉工作流，再连接真实车辆。

> 安全提示：首次连接真实车辆前，请让驱动轮离地、限制 PWM/电流，并准备立即断电。参数写入 RAM 后可能立刻改变车辆行为。

## 1. 安装与启动

Windows 发布目录提供两个版本：

- `DiCar-Tune-0.1.2-Windows-x64-Setup.exe`：标准安装版。
- `DiCar-Tune-0.1.2-Windows-x64-Portable.exe`：便携版，直接运行。

两者功能相同，均包含内置模拟器。发布文件尚未进行商业代码签名，Windows 首次启动可能显示 SmartScreen 提示。请确认文件来自项目发布目录，并可用以下 SHA-256 核对：

```text
Setup:    E349F511709CEB4854C3ABB2F0B9CCC9307649CE88FDA867FCAAE6C93D056EB3
Portable: 2A46F473E0EE7E797EBA30F5EFD063D1E18C3A33788B211C242A46C5AAC71984
```

启动后顶部状态栏显示当前连接方式、端点和连接状态。只有完成 DCTP 握手、Manifest 加载和参数读取后，状态才会变为“已连接”。打开 COM 口本身不算连接成功。

## 2. 使用内置模拟器

内置模拟器用于熟悉界面、验证参数工作流和观察动态波形，不需要外部硬件或单独启动服务。

1. 在顶部连接方式中选择“模拟器体验”。
2. 点击“连接模拟器”。
3. 确认状态变为“已连接”，首页参数数量和遥测通道数量不再为 0。
4. 打开“实时调参与波形”。
5. 修改参数后点击“写入 RAM”。成功 ACK 后，RAM 值和 Revision 才会更新。
6. 点击“审阅并固化”查看 RAM/Flash 差异，再执行模拟固化。
7. 点击“断开设备”结束会话。

如果模拟器连接出现 Windows `10061` 拒绝连接错误，通常说明运行的是旧版或不完整副本。0.1.2 已将模拟器直接打包进 App，请重新下载当前版本。

## 3. 连接真实车辆前的准备

真实连接需要同时满足以下条件：

- 车端 MCU 运行与 App 兼容的 DCTP v1 固件。
- MCU UART 和无线模块配置为相同的波特率、数据位、停止位和校验方式。
- MCU TX 接模块 RX，MCU RX 接模块 TX。
- MCU 与无线模块必须共地。
- 串口 IO 电平兼容；不能把 5 V 逻辑直接送入仅支持 3.3 V 的 RX。
- Windows 能看到电脑端 USB 串口或 Bluetooth SPP 虚拟 COM。
- 串口没有被串口助手、下载器或另一个 DiCar Tune 进程占用。

无线模块只负责透明传输字节，不会自动理解参数，也不能替代 DCTP 固件。当前 App 的真实硬件入口用于调参和遥测，无线固件烧录流程尚未接入 UI。

## 4. nanoUART-wl

### 接线

按模块丝印和卖家资料确认供电后连接：

| nanoUART-wl 车端 | MCU |
| --- | --- |
| `3V3` | 3.3 V 电源 |
| `GND` | GND |
| `TX` | MCU RX |
| `RX` | MCU TX |

不要只连接 TX/RX 而省略共地。若实际硬件版本的供电或 IO 规格不同，以模块丝印和硬件说明为准。

### Windows 连接

1. 将电脑端模块插入 USB，等待 Windows 创建设备 COM。
2. 在 DiCar Tune 选择“真实串口”。
3. 硬件类型选择“nanoUART-wl”。
4. 选择刚出现的 COM。
5. 波特率建议选择“自动探测”。
6. 点击“连接真实设备”。

自动探测顺序为：

```text
460800 → 230400 → 115200 baud
```

App 会逐个速率尝试 DCTP 会话，只有握手和设备加载成功后才停止并保存该设置。460800 baud 配置允许最高 8 通道 × 500 Hz；较低波特率会降低安全上限。

## 5. HC-05 蓝牙串口

HC-05 使用 Bluetooth Classic SPP，在 Windows 中表现为虚拟 COM。它不是 Web Bluetooth 设备；本项目通过 Windows 桌面 App 的串口入口访问它。

### 车端接线

| HC-05 | MCU |
| --- | --- |
| `VCC` | 按具体底板标注供电 |
| `GND` | GND |
| `TXD` | MCU RX |
| `RXD` | MCU TX，经必要的电平转换 |

HC-05 UART 按 3.3 V 逻辑处理。若 MCU TX 为 5 V，发往 HC-05 RXD 的信号必须分压或使用电平转换；不要仅依据底板 VCC 可接 5 V 就推断 RXD 可承受 5 V。

### Windows 配对与 COM 选择

1. 给车端 HC-05 上电，使其进入可配对状态。
2. 在 Windows“蓝牙和设备”中完成配对；配对码以模块配置为准。
3. 打开“更多蓝牙设置”中的“COM 端口”页面。
4. 找到 HC-05 对应的**传出（Outgoing）COM**。
5. 在 DiCar Tune 选择“真实串口 → HC-05 蓝牙串口 → 传出 COM”。
6. 波特率选择“自动探测”，然后连接。

不要选择同一设备的传入 COM。自动探测顺序为：

```text
115200 → 9600 → 38400 → 57600 → 230400 → 460800 baud
```

HC-05 普通连接默认限制为 4 通道 × 50 Hz；如果仅能以 9600 baud 连接，则限制为 2 通道 × 10 Hz。该限制用于为协议 ACK、重试和控制消息保留带宽，不代表对所有 HC-05 模块吞吐性能的硬件认证。

## 6. 实时调参工作流

实时工作台由参数导航、参数编辑和遥测波形组成。

### 选择和管理车型配置

- “通用 Manifest”直接按设备分组显示全部参数和遥测，适合未知车型或排查兼容性。
- “DiCar 差速车”内置配置提供速度环、编码器标定、底盘几何和波形预设。
- 点击车型选择器旁的齿轮可导入 `.yaml`/`.yml`；相同用户 ID 必须点击“确认替换”，移除当前配置会回到通用模式。
- 用户配置最多 16 个、合计 2 MiB，单文件最多 256 KiB；不能覆盖内置车型 ID。

配置中的参数和通道名必须与设备 Manifest 的 `machine_name` 完全一致并区分大小写。兼容性提示表示某些引用在当前设备上不存在或不适用；App 会保留有效部分，“全部参数”仍提供完整设备清单。车型配置只负责页面组织，不会改变设备声明的类型、范围、只读状态，也不会伪造目标参数或自动写入。

1. 在左侧按分组或名称找到参数。
2. 在中间面板确认类型、单位、范围、步进、危险标记、当前 RAM、Flash 和 Revision。
3. 修改目标值，点击“写入 RAM”。
4. 等待设备 ACK；App 不会在 ACK 前把目标值伪装成设备真值。
5. 先观察车辆响应和波形，再继续修改。
6. 确认一组修改稳定后，点击底部“审阅并固化”。
7. 在弹窗核对所有待固化项目，使用 Owner 身份且控制权有效时写入 Flash。

选择速度环任务时，波形区会一次性预选目标、实际、误差和输出通道。此时不会向设备发送订阅；确认通道和采样率后仍需点击“应用 … Hz 订阅”。之后的手动通道选择不会被同一任务重复覆盖。

本地演示角色：

- `Owner`：控制权有效时可写 RAM 和固化 Flash。
- `Tuner`：控制权有效时可写 RAM，但不能固化 Flash。
- `Observer`：只能查看状态和波形。

这些角色用于展示产品策略，不构成云端身份认证或分布式安全边界。

### 保存与应用参数方案

页面顶部的"参数方案"按钮用于把调好的一组参数存下来，之后随时恢复：

- **保存**：把当前全部参数的 RAM 值存为一个命名方案，可附一句说明（例如赛道和电池状态）。方案保存在本机，最多 64 个、合计 1 MiB。
- **应用**：按稳定参数 ID 与当前设备匹配，先展示逐项差异再写入。设备缺失、类型变化、超出当前范围、只读或状态未知的项只会列出，不会自动写入。应用写的是 RAM，不会自动固化到 Flash。
- **固化记录**：每次固化成功后自动生成一条记录，标注设备的存储 Generation，方便追溯"哪个版本在 Flash 里"。
- **导出**：任意方案可导出为可读 JSON，适合提交到你自己的项目仓库存档。

`Observer` 不能保存或应用方案；应用方案与写参数一样需要有效控制权。方案数据只存在本机，不会写入设备，重装系统或清除浏览器数据前请先导出。

## 7. 编码器参数

编码器面板明确区分以下概念：

- 左/右 `PPR`：编码器每机械转输出的基础脉冲数。
- 正交倍频：×1、×2 或 ×4。
- 左/右 `CPR`：根据 PPR 和倍频计算的只读计数值，不应作为另一份独立标定值修改。
- 左/右方向反向：修正安装方向与计数符号。
- 车轮直径和传动比：用于从计数换算车速。
- 采样周期、速度低通、跳变阈值、可信最高转速和缺脉冲检测：用于测速稳定性与异常判断。

调整步骤建议：

1. 在车辆静止、轮胎离地时确认左右计数方向。
2. 设置数据手册给出的 PPR 和实际正交倍频。
3. 手动转动车轮一圈，核对原始计数和只读 CPR。
4. 设置轮径和传动比，再核对计算速度。
5. 最后调整采样周期、低通和异常阈值。

## 8. 遥测波形与链路上限

波形区支持：

- 选择通道和采样率；
- 最多 60 秒有界缓冲；
- 暂停/继续；
- 1、5、10、30、60 秒窗口；
- 键盘左右键移动历史游标；
- `M` 添加时间标记；
- 图例、精确读数和数据表。

App 会根据当前连接端点给出链路预算，并在核心层拒绝超限订阅：

| 链路 | 最大通道 | 最大采样率 |
| --- | ---: | ---: |
| 内置模拟器 | 8 | 500 Hz |
| nanoUART-wl 460800 baud | 8 | 500 Hz |
| HC-05 普通模式 | 4 | 50 Hz |
| HC-05 9600 baud | 2 | 10 Hz |

通用串口和较低速率 nanoUART-wl 会按波特率自动缩小预算。诊断页显示当前配置、实际安全上限、CRC、重试、序列缺口和丢样计数。

## 9. RAM、Flash 与断线状态

- `RAM` 是当前设备正在使用的参数值。
- `Flash` 是设备重新上电后恢复的已固化值。
- `Revision` 每次设备确认 RAM 写入后递增，用于检测并发或过期修改。
- `Dirty` 表示 RAM 与 Flash 的线级值不同。

断线后，App 会把设备真值标记为未知并停止写入，不会自动重放旧的待发送操作。重新连接后必须重新握手、读取 Manifest 和参数状态。固化操作按完整计划一次确认；失败时不能把部分参数误报为已写入 Flash。

## 10. 常见问题

### 找不到 COM

- USB 模块：重新插拔并在设备管理器中确认端口和驱动。
- HC-05：确认已完成 Windows 配对，并选择传出 COM。
- 关闭可能占用串口的串口助手、下载器或另一个 App 实例。

### 显示“拒绝访问”或端口占用

同一 COM 通常只能被一个程序打开。关闭其他串口程序后重试；必要时拔插模块或重新连接 Bluetooth SPP。

### 自动探测全部失败

依次检查：

1. COM 是否选对，HC-05 是否为传出 COM。
2. TX/RX 是否交叉且已经共地。
3. MCU UART 与无线模块的运行波特率是否一致。
4. MCU 是否运行 DCTP 固件，而不是普通文本串口程序。
5. 供电、电平和模块工作模式是否正确。

### 已连接但无法写参数

- Observer 只能查看。
- Owner/Tuner 必须具有当前控制权。
- 参数可能只读、类型不匹配或超出设备范围。
- Revision 冲突时以设备返回的当前 RAM 和 Revision 为准，再决定是否重试。

### 波形通道或采样率无法继续提高

这是链路预算保护，不是界面故障。降低通道数或采样率；HC-05 不建议承担 8 通道 × 500 Hz 的持续遥测。

## 11. 当前限制

- 无线固件烧录尚未接入 UI。
- 纯 Web 客户端仅提供模拟体验和浏览器串口授权入口，尚无真实 DCTP 会话。
- 云账户、团队协作、远程控制和插件市场尚未实现。
- 自动 PID、AI 调参建议和多车并发尚未实现。
- 手机、平板、macOS 和 Linux 客户端尚未发布。
- 当前软件兼容层已覆盖 nanoUART-wl 与 HC-05，但不同模块版本、天线、电源、固件和赛场干扰条件仍需实体测试。
